整體平台架構

平台以 Agno AgentOS 執行 Agent、Team 和 Workflow。Backstage 提供目錄入口，LibreChat 提供對話介面，Langfuse 記錄執行觀測資料。

Backstage · 目錄

查詢 26 個 Agent、3 個 Team、14 個 Skill 與 2 個 Workflow；Agent 頁的 Relations 圖顯示可能的前後序、Team 成員和 Skill 依賴。

LibreChat · 對話

選擇 Agent 或 Team 發送文字。Gateway 轉換請求，並依使用者、對話與目標建立 AgentOS session。

AgentOS · 執行

保存並執行 Agent、Team 和 Workflow 定義。PAY-482 透過證據判斷、委派、並行提案與人工審查完成示範。

Langfuse · 觀測

接收 AgentOS 的 OpenTelemetry 資料，可用 Tree、Graph 和 Timeline 檢視呼叫與耗時。

資料如何流動

Agent、Team、Skill 與 Workflow 定義檔 → Python 部署流程驗證並建立版本快照 → 同一版本產生 AgentOS 設定、Backstage Catalog 與 LibreChat 選單 → Gateway 呼叫 AgentOS → AgentOS 傳送 Trace 給 Langfuse。

Backstage 關係圖由靜態 Workflow 定義推導可能交接，dependsOn 指向前序或使用的 Skill；Team 代表可委派成員。下方互動圖與 Langfuse 實拍呈現先前保存的 PAY-482 執行資料，不能視為目前定義版本已重新執行的證明。

服務用途資料
Backstage / PostgreSQLAgent、Team、Skill、Workflow 目錄及可能交接Catalog 由版本化定義檔匯出，資料庫保存在專用 volume。
LibreChat / MongoDB登入、選擇 Agent 或 Team、文字對話帳號與對話保存在專用 volume。
Agno Gateway把 LibreChat 的 Chat Completions 請求轉換為 AgentOS 請求每次請求附上文字歷史，AgentOS 憑證由伺服器保管。
AgentOS / PostgreSQL執行並保存 Agent、Team 與 Workflow 的狀態沿用現有資料庫。
Langfuse / ClickHouse / PostgreSQL / Redis / 物件儲存執行觀測與追蹤沿用現有 Langfuse 資料。

Gateway 支援文字，回覆完成後再傳送。Backstage 顯示靜態定義關係；實際委派、執行次序及結果應查看 Langfuse。送審前會檢查必要 Agent 步驟，失敗或缺少結果時回傳 UNKNOWN。定義部署可驗證、建立本機快照及回滾，但不回滾程式碼或資料庫。

PAY-482 案例

付款供應商送出 webhook。帳務服務完成入帳，但回應途中逾時。供應商用相同事件 ID 重送，系統若再寫一筆，帳上就會出現重複入帳。修補目標是讓同一事件只入帳一次，同時保留不同事件各自入帳的行為。

首次送達事件 event-1 完成入帳。
回應逾時供應商未收到確認。
同事件重送再次收到 event-1。
預期結果只保留原本一筆入帳，event-2 仍可新入帳。

證據範圍　付款服務、CI、版本及核准是本機示範資料。實際執行的是記憶體帳本的兩項 unittest，以及 AgentOS 模型呼叫與 Workflow。兩項測試覆蓋順序重送及不同事件；併發、交易資料庫、簽章及正式發布仍待驗證。

情境送入 Gate 的條件路徑
ready模擬候選與受測版本皆為 a1b2c3d，本機測試通過。專家規劃、平行建議、Reviewer 與風險整理，最後等待人工審查。
stale模擬 CI 綠燈對應 f0e1d2c，候選為 a1b2c3d。NOT READY，需對當前版本補跑。
timeout模擬 CI 查詢逾時，缺少可用的 CI 結果。UNKNOWN，等待補證。
fail模擬併發重送檢查得到兩筆入帳；本機順序單測仍通過。NOT READY，需修正後重新執行。
